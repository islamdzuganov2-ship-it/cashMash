# CashMash Scalper — версия для телефона

Торговый бот для криптобиржи **Bybit** (USDT-перпетуалы), запускаемый на
Android как обычное приложение.

> **Ветка `mobile`.** Здесь то же ядро робота, что и везде, плюс сборка
> приложения в `android/`. Убрано то, что на телефоне неисполнимо:
> Docker и systemd, автозапуск Windows, исследовательский инструментарий
> и аналитик с локальной языковой моделью.
>
> Версия для компьютера — ветка [`pc`](https://github.com/islamdzuganov2-ship-it/cashMash/tree/pc).
> Полный проект с обеими оболочками — [`main`](https://github.com/islamdzuganov2-ship-it/cashMash/tree/main).

**Торгующая часть — тот же код, файл в файл.** Всё в `src/` — сигнал,
риск, исполнение, учёт позиции, состояние — совпадает с `main` побайтово,
и проверяется теми же тестами. Разойдись оно поведением, и проверка на
компьютере перестала бы что-либо значить.

Расходится только обвязка, и ровно в одном месте: вместе с аналитиком из
панели и из реестра служб убрана карточка разбора. Что именно и почему —
[в конце](#чего-в-этой-ветке-нет).

## Почему Android, а не iOS

Робот — долгоживущий процесс: он держит открытым WebSocket к бирже,
строит бары и не умеет «просыпаться по запросу». Разница между
системами ровно в том, разрешают ли они такой процесс.

| | Android | iOS |
|---|---|---|
| CPython внутри приложения | **да**, Chaquopy встраивает его в APK | нет: исполнение загруженного кода запрещено |
| Долгоживущий процесс | **да** | нет: система выгружает фоновые задачи |
| Автозапуск после перезагрузки | **да** | нет |
| Панель как приложение (PWA) | да | **да** |

На iOS ставится только панель — экран к роботу, который работает
где-то ещё. Обещать «робот на айфоне» было бы неправдой: ограничение
не в этом коде. Подробности: [docs/33-Mobile.md](docs/33-Mobile.md).

## Сборка приложения

Нужна машина с Android SDK и Python 3.13 — тем же, что зашит в
`android/app/build.gradle.kts`: этим интерпретатором Chaquopy запускает
pip, собирая колёса под Android. Расхождение младших версий означало бы,
что «проверено» и «работает» — про разные интерпретаторы.

```bash
cd android
./gradlew assembleDebug     # app/build/outputs/apk/debug/
./gradlew installDebug      # сразу на подключённый телефон
```

`android/local.properties` в репозиторий не входит — у каждой машины
пути свои:

```properties
sdk.dir=C:/Users/имя/AppData/Local/Android/Sdk
chaquopy.buildPython=C:/путь/к/проекту/.venv/Scripts/python.exe
```

Собираются отдельные APK на `arm64-v8a` и `x86_64` плюс универсальный:
телефону нужен ровно один набор нативных библиотек, а Python с
зависимостями — это почти весь вес.

### Что попадает в APK

Настоящий CPython, три библиотеки (`websockets`, `requests`, `PyYAML`)
и дерево робота — `src/`, `ops/`, `config/`, `research/collect_bybit.py`.

`ops/.env` не попадает **никогда**: APK копируют, пересылают и забывают
в загрузках, а там токен Telegram и, возможно, ключи биржи. На телефоне
файл создаётся заново, из настроек приложения, и лежит во внутренней
памяти.

## Что телефон делает по умолчанию

**Наблюдает.** Включены панель, виртуальная торговля, наблюдатель
новостей и доставка сообщений. Руками, в настройках, включаются:

| Служба | Чем дорога телефону |
|--------|---------------------|
| запись истории | около 65 МБ в сутки |
| торговый процесс | требует ключей биржи; без них откажется торговать |

Службы здесь — потоки одного процесса, а не отдельные процессы:
Chaquopy даёт интерпретатор библиотекой, исполняемого файла `python` на
телефоне не существует. Этим занимается `ops/android_run.py`; он же
хранит общий перечень служб, по которому работает и супервизор на
компьютере.

## Второй путь: Termux

Приложение появилось позже и заменило этот способ, но он рабочий и
остаётся в ветке. Termux даёт настоящее Linux-окружение, а
`termux-wake-lock` не даёт системе усыпить процесс.

```bash
sh ops/android_termux.sh
```

Нужны Termux и Termux:Boot **из F-Droid** — версия из Google Play
устарела и не обновляется.

## Подключение биржи и алерты

Пока счёт не подключён, робот только наблюдает: без ключа невозможна
сверка с биржей, а торговать без сверки нельзя — принцип fail-closed.
Это не ошибка и не недоделка.

Ключ с правом **Withdraw** не принимается вообще: торговле это право не
нужно, а утечка файла с таким ключом означает потерю счёта, а не убыток
по сделке ([docs/10-Security.md](docs/10-Security.md), 10.2).

Ключ вводится в настройках приложения. В панели приём ключей разрешён
только с самой машины робота: HTTP не шифрован, и секрет, отправленный
по сети, виден всем на пути.

Токен Telegram-бота — там же, в настройках. Образец полей:
[ops/.env.example](ops/.env.example).

## Чего в этой ветке нет

Всё перечисленное осталось в [`main`](https://github.com/islamdzuganov2-ship-it/cashMash/tree/main)
и в [`pc`](https://github.com/islamdzuganov2-ship-it/cashMash/tree/pc):

| Убрано | Почему |
|--------|--------|
| `LLM/`, `ops/analyst.py` и карточка разбора в панели | аналитик поднимает языковую модель на несколько гигабайт; телефону это не по силам ни по памяти, ни по батарее |
| `ops/Dockerfile`, `docker-compose.yml`, `cashmash.service` | развёртывание на сервере; к Android неприменимо |
| `ops/install_autostart.ps1`, `ops/collect.cmd`, `CashMash.cmd` | автозапуск и ярлыки Windows |
| `CashMash.command` | ярлык macOS |
| `research/` — всё, кроме сборщика и `gzio.py` | скринеры, бэктесты и измерения: гигабайты истории и часы счёта |
| `archive/mt5-superseded/` | снятая ветка MetaTrader 5 |

Аналитик убран не одним удалением каталога: вместе с ним ушли служба из
реестра `ops/android_run.py`, обработчик `/api/analyst/*` и карточка
«Разбор работы робота» из панели. Оставить их значило бы держать на
экране телефона кнопку, которая не может сработать.

Разбор работы робота никуда не делся — он живёт в ветках
[`main`](https://github.com/islamdzuganov2-ship-it/cashMash/tree/main) и
[`pc`](https://github.com/islamdzuganov2-ship-it/cashMash/tree/pc), где
есть чем поднять модель. Телефон и компьютер смотрят в одни и те же
`data/`, так что разбор, сделанный на компьютере, описывает ту же
работу.

Документация оставлена целиком, включая [docs/34-Analyst.md](docs/34-Analyst.md):
это техническое задание на систему, а не на одну её оболочку.

## Принцип

> Задача — не написать бота, а выяснить, существует ли преимущество,
> превышающее издержки. Бот — инструмент измерения; в случае
> положительного ответа он становится инструментом эксплуатации.

Отрицательный результат валидации — успешное завершение фазы, а не
провал проекта.
