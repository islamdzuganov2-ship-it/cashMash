# CashMash Scalper

Торговый бот для криптобиржи **Bybit** (USDT-перпетуалы) и исследовательский контур к нему.

**Статус:** фаза 0 закрыта. Инструмент выбран, модель издержек построена, сборщик данных готов к запуску.

> Версия 1.0 ТЗ была написана под MetaTrader 5. После уточнения площадки пакет переписан под Bybit; старые наработки — в `archive/mt5-superseded/`.

## Быстрый старт

```bash
python -m venv .venv
.venv/Scripts/pip install websockets requests
```

**Запустить прямо сейчас и не выключать** — сбор истории стакана. Стратегия входит post-only лимитной заявкой, и без истории книги её нельзя честно протестировать. Данные накапливаются только вперёд:

```bash
.venv/Scripts/python research/collect_bybit.py --symbol XRPUSDT
```

~65 МБ в сутки. Переживает жёсткое завершение процесса. API-ключ не нужен, ничего не торгует.

## Ключевые решения

| Решение | Обоснование |
|---------|-------------|
| Перпетуалы, не спот | круг 7.5 bps против 20 bps; возможен шорт |
| XRPUSDT | мин. ордер ровно 5 USDT → плечо 1x; спред 0.72 bps; оборот $561 млн/сут |
| Экспозиция 1x, маржа изолированная | плечо не используется как усилитель риска |
| Python + asyncio | узкое место — сеть (10–80 мс), не вычисления (0.1 мс) |
| Вход post-only | 2.0 bps вместо 5.5 — снижает издержки круга на 32% |
| Стоп всегда на бирже | локальный умирает вместе с процессом |
| Данные: архивы Bybit + свой сбор | архивы отвечают «есть ли что ловить», свой сбор даёт стакан |
| Фиксированная точка выхода в сеть | хостинг меняется, а привязка ключа к IP должна работать |
| Алерты отдельным процессом | зависший вызов к Telegram не должен морозить торговый цикл |
| `Decimal`, никогда `float` | биржа отклоняет количества, не кратные `qtyStep` |

## Главные числа

**Издержки:**

```
Круг (maker вход + taker выход):  7.5 bps
Спред XRPUSDT:                    0.72 bps
C_total:                          ≈ 8.2 bps
Минимальное осмысленное движение = 3 × 8.2 ≈ 0.25%
```

**Сколько должен дать сигнал** — измерено на 21 дне истории ([docs/24-Movement-Study.md](docs/24-Movement-Study.md)):

```
Геометрия 50/20 bps (RR 2.5), горизонт 15 мин:
  случайный вход даёт         29.7% успеха
  безубыток требует           44.5%
  ─────────────────────────────────────────
  сигнал обязан добавить     +14.8 п.п.
```

Планка высокая. Но теперь это измеримая цель, а не надежда: любая гипотеза проверяется одним вопросом.

**Что ещё показало измерение:** волатильности достаточно (81% пятнадцатиминутных окон дают ≥25 bps); рынок — честная игра минус издержки (гонка барьеров 49.3/50.7, матожидание случайного входа ровно −8 bps); горизонты короче 5 минут не окупаются; активность концентрируется в 13:00–19:00 UTC.

## Робот на телефоне

Android запускает робота целиком — приложением, без терминала и без
Termux. Внутри APK настоящий CPython, те же службы и та же панель, что
на компьютере; отдельной «мобильной версии робота» нет и быть не должно.

```bash
cd android
./gradlew installDebug        # на подключённый телефон
```

Перед первой сборкой в `android/local.properties` укажите путь к Android
SDK и к Python 3.13 — им Chaquopy запускает pip. По умолчанию телефон
**наблюдает**: панель, виртуальная торговля, новости, сообщения. Запись
истории (65 МБ в сутки) и торговля включаются руками, в настройках.

iOS робота не запустит: система не разрешает ни фоновый процесс, ни
исполнение загруженного кода — туда ставится только панель. Подробности
и цена решений: [docs/33-Mobile.md](docs/33-Mobile.md).

## Разбор работы робота

Робот торгует сам. Локальная модель в его работу не вмешивается — она
читает следы и отвечает на вопрос «почему получилось так»: куда ушло
движение, что сделала комиссия, достижима ли вообще цель при
наблюдаемом размахе.

```bash
.venv/Scripts/python ops/analyst.py status   # что готово, чего не хватает
.venv/Scripts/python ops/analyst.py run      # проверить и разобрать
.venv/Scripts/python ops/analyst.py ask "почему углубилась просадка?"
```

То же — кнопкой в панели, карточка **«Разбор работы робота»**. Сама по
себе служба разбирает сутки раз в день, в 21:00 UTC — после того, как
спадает активность рынка.

**Главное в устройстве:** числа считает Python, модель их только
связывает. Перед публикацией каждое утверждение сверяется с
посчитанным, и число, которого нет среди оснований, снимает
утверждение целиком — снятое печатается отдельным разделом с причиной.
Поэтому отчёт беднее, чем написал бы чат, и проверяем: у каждого числа
виден источник.

Обучение при этом не трогает веса. Система накапливает утверждения о
конкретном роботе и перепроверяет их на сделках, которых они не
видели; три подтверждения переводят гипотезу в знание, два
опровержения — в архив. Дообучение весов ниже 500 сделок система
делать отказывается и объясняет, почему.

Модель — любой файл `.gguf`: по умолчанию единственный в `LLM/`, либо
заданный путём в `LLM/analyst.json` (тогда копия не нужна — можно
указать на хранилище LM Studio). Имя нигде не зашито. Запустить можно
через llama.cpp, LM Studio или Ollama; способ выбирается сам.

Оценка качества хранится вместе с именем модели, на которой получена.
Заменили модель — готовность откажет, пока не прогнан `check`: балл
принадлежит модели, а не системе. Подробности:
[docs/34-Analyst.md](docs/34-Analyst.md).

## Подключение биржи

Пока счёт не подключён, робот только наблюдает: без ключа невозможна
сверка с биржей, а торговать без сверки нельзя — принцип fail-closed
переводит его в `MANAGE_ONLY`. Это не ошибка и не недоделка.

У Bybit нет «входа по паролю»: доступ от вашего имени даёт API-ключ.
**Пароль от аккаунта роботу не нужен, и вводить его некуда.**

```bash
.venv/Scripts/python ops/bybit_login.py            # подключить (testnet)
.venv/Scripts/python ops/bybit_login.py --status   # что подключено
.venv/Scripts/python ops/bybit_login.py --check    # перепроверить на бирже
.venv/Scripts/python ops/bybit_login.py --logout   # забыть ключ
```

То же есть в панели — карточка **«Подключение биржи»**. Ключ там
принимается только с самой машины робота: HTTP не шифрован, и секрет,
отправленный по сети, виден всем на пути. С телефона или другого
компьютера — либо SSH-туннель на `127.0.0.1`, либо консоль. Совсем
запретить приём ключей в панели: `ops/dashboard.py --no-connect`.

Что происходит при подключении:

| Шаг | Что делает робот |
|-----|------------------|
| 1 | Синхронизирует часы с биржей — иначе подпись отвергается, и виноватым выглядит ключ |
| 2 | Спрашивает `/v5/user/query-api`: права, срок, привязка к IP |
| 3 | **Отказывает**, если у ключа есть Withdraw, если он Read-Only или без прав на торговлю |
| 4 | Предупреждает, если ключ не привязан к IP, скоро истекает или это MAINNET |
| 5 | Читает баланс и только теперь записывает ключ в `ops/.env` (права 600) |
| 6 | Супервизор замечает новый ключ и перезапускает торговый процесс сам |

Ключ с правом **Withdraw** не принимается вообще: торговле это право не
нужно, а утечка файла с таким ключом означает потерю счёта, а не убыток
по сделке ([docs/10-Security.md](docs/10-Security.md), 10.2).

Подключение даёт роботу читать баланс и позиции, ставить и снимать
заявки, держать стоп на бирже. **Входы в рынок им не включаются:** для
них нужен режим `LIVE` в конфиге и сигнальный слой, которого пока нет
(фаза 2). В `SIGNAL_ONLY` робот с подключённым ключом сверяется с
биржей и ведёт учёт, но не отправляет ни одного ордера.

## Принцип

> Задача — не написать бота, а выяснить, существует ли преимущество, превышающее издержки. Бот — инструмент измерения; в случае положительного ответа он становится инструментом эксплуатации.

Отрицательный результат валидации — успешное завершение фазы, а не провал проекта.
