# ✅ 17 · Критерии приёмки

Каждая фаза закрывается **гейтом**. Гейт — это набор проверяемых условий; невыполненное условие означает возврат на фазу, а не «ну почти».

## 17.1 Гейт 0 — ТЗ, инструмент, модель издержек ✅

```
✅ Платформа, рынок и инструмент выбраны (Bybit, linear perp, XRPUSDT)
✅ Спецификации сняты: minNotional 5 USDT, спред 0.72 bps, оборот $561 млн
✅ Модель C_total построена: 7.5 bps (maker вход + taker выход)
✅ Подтверждено: минимальное осмысленное движение ≈ 0.25%
□ Комиссионный уровень аккаунта проверен: GET /v5/account/fee-rate
□ Источник исторических данных выбран (Q8)
□ Замерен RTT из предполагаемой локации хостинга (Q9)
□ Репозиторий, CI, структура артефактов созданы
```

## 17.2 Гейт 1 — Каркас: API-слой, исполнение, риск, надёжность

Фаза принимается, когда бот **без сигнального слоя** (входы по тестовому триггеру) отрабатывает механику безупречно.

**Состояние на 19.09.2026: 155 тестов зелёных, ключевые пункты закрыты.**

```
✅ Юнит-тесты: 155 зелёных, выполняются за 10 с, сети не требуют
✅ Мок-биржа с адресной инъекцией сбоев: таймаут, 403, 429, все классы
   retCode, отказ сверки, отказ выставления стопа
✅ 1000 циклов движка — ноль дублей, каждое решение с внятной причиной
✅ 500 циклов под случайными сбоями — идемпотентность держится
✅ Идемпотентность: таймаут + ИСПОЛНЕННЫЙ ордер → дубля нет
✅ Сверка не прошла → повтора нет, запись остаётся открытой
✅ Три неудачи выставления стопа → аварийное закрытие позиции
✅ Расчётный объём ниже minNotional → отказ, а не невалидный запрос
✅ Риск не превышает заданный ни при каком округлении
✅ Дневной baseline переживает перезапуск процесса
✅ Кросс-маржа при плече запрещена конфигом
✅ Разрыв последовательности стакана → торговля запрещена
✅ Отказ логирования не роняет торговлю
✅ Сквозной прогон против живого Bybit: 149 решений за 38 с, 0 разрывов
□ mypy --strict без ошибок на торговом коде
□ Testnet с ключами: 1000 циклов без 10006 и 403
□ Watchdog: kill -9 → подъём; 3 перезапуска за час → стоп + алерт
□ Kill-switch FLATTEN отрабатывает за < 5 сек на реальном ордере
□ Разрыв WS при открытой позиции → после реконнекта состояние верное
```

> Проверено сквозным запуском 19.09.2026: **без API-ключей реконсиляция не проходит, и бот отказывается торговать**, переходя в `MANAGE_ONLY`. Это ровно то поведение, которое задумано принципом fail-closed: не зная, сколько у тебя позиций, торговать нельзя.

> Этот гейт — самый важный и самый скучный. Стратегию можно менять бесконечно; механика исполнения либо надёжна, либо нет.

## 17.3 Гейт 2 — Сигнальный слой, In-Sample

> **Главный численный критерий, полученный измерением** ([[24-Movement-Study]]): при геометрии 50/20 bps случайный вход даёт 29.7% успеха. Дальше важно не перепутать два порога:
>
> | Порог | Значение | Смысл |
> |-------|----------|-------|
> | Безубыток | **44.5%** | матожидание ровно ноль — торговать бессмысленно |
> | **Рабочий порог** | **48.5%** | чистый эдж ≥ 5 bps на сделку, как требует гейт издержек |
>
> Критерием приёмки является **второй**. Стратегия, выходящая ровно в безубыток, не зарабатывает ничего и при первом же ухудшении исполнения становится убыточной. **Сигнал обязан добавить ≥ 18.8 п.п.** к рыночным 29.7%.
>
> Расхождение обнаружилось при сквозной проверке на живых данных: гейт издержек отклонял сделку при p_win = 44.5%, хотя документ называл это значение достаточным. Прав оказался гейт.

```
□ Доля успешных сделок ≥ 48.5% при геометрии 50/20 bps
  (для иной геометрии считается так же: сначала безубыток
   p_be = (cost/(1-f_timestop) + SL) / (TP + SL), затем рабочий порог
   из условия «чистый эдж ≥ min_net_edge_bps»)
□ Число сделок IS ≥ 500
□ Expectancy после издержек > 0
□ Expectancy > 0 при УДВОЕННЫХ издержках
□ t-stat средней сделки ≥ 3.0
□ Profit factor ≥ 1.25 (или ≥ 1.15 при N ≥ 2000)
□ Max relative equity DD ≤ 15%
□ Максимальная серия убытков ≤ 8
□ Доля прибыли от топ-5 сделок ≤ 30%
□ ≥ 60% месяцев прибыльны
□ Число одновременно оптимизированных параметров ≤ 4
□ trials.csv ведётся, число попыток зафиксировано честно
```

## 17.4 Гейт 3 — Out-of-Sample и робастность

```
WALK-FORWARD
□ WFE ≥ 0.5
□ Доля прибыльных OOS-окон ≥ 60%
□ Суммарное число OOS-сделок ≥ 300
□ t-stat на склеенном OOS ≥ 2.0

CPCV
□ Медиана OOS-Sharpe > 0
□ Доля положительных комбинаций ≥ 65%
□ 5-й перцентиль просадки не превышает лимит счёта

ПЕРЕОБУЧЕНИЕ
□ PBO < 0.5 (целевое < 0.3)
□ Deflated Sharpe Ratio: p < 0.05 при честном числе trials

РОБАСТНОСТЬ
□ Сенситивность: ≥ 70% соседних точек (±30%) положительны
□ Выбранная точка лежит на плато, не на пике
□ Стресс издержек ×2: expectancy > 0
□ Стресс латентности 250 мс: деградация < 40%
□ Монте-Карло перестановок: p95 просадки ≤ InpMaxTotalDDPct
□ Бутстрап: доля убыточных траекторий < 5%
□ Удаление топ-5% сделок: стратегия остаётся прибыльной
□ Сдвиг стартовой даты на 1–20 дней: разброс < 30%
□ Нет года с провалом > 2× типичной просадки
```

## 17.5 Гейт 4 — Testnet (4 недели)

```
□ 4 полные недели непрерывной работы
□ Ноль инцидентов класса FATAL по вине бота
□ Uptime ≥ 99%
□ Ноль HTTP 403, ноль retCode 10006
□ Maker ratio ≥ 80%
□ Число сделок: ±15% от бэктеста на том же периоде
□ Winrate: ±7 п.п.
□ Средняя сделка в bps: ±25%
□ Фактический C_total ≤ модельный × 1.3
□ Уплаченный фандинг ≈ 0
□ Max DD ≤ модельная × 1.5
□ Еженедельные отчёты сформированы, аномалий нет
```

Расхождение сверх допустимого = **дефект модели**, возврат на Гейт 2 с уточнёнными издержками. Не «рынок изменился».

> Оговорка: на testnet другая ликвидность и другие задержки, поэтому метрики исполнения там **оптимистичны**. Гейт 4 проверяет отсутствие отказов, а не точность экономики — её проверяет Гейт 5.

## 17.6 Гейт 5 — Live $5 (4 недели)

Проверяется **исправность механики на реальных деньгах**, не прибыльность.

```
□ confirm_mainnet выставлен осознанно, ключ с IP-привязкой, без Withdraw
□ 4 недели непрерывной работы
□ Ноль инцидентов, потребовавших ручного вмешательства
□ Ноль позиций без биржевого стопа
□ Ноль дублей позиций
□ Maker ratio ≥ 80% — подтверждение, что экономика реализуется
□ Фактическая комиссия в bps совпадает с моделью ±10%
□ Фандинг списывается и учитывается корректно
□ Реконнекты и перезапуски не ломают учёт
□ Заполнен CHANGELOG-PROD
```

**Чего этот гейт НЕ проверяет:** прибыльность. При фиксированном минимальном размере позиции выборка не позволяет сделать статистический вывод. Попытка объявить стратегию рабочей по результатам $5 — главная ошибка этого этапа.

## 17.7 Гейт 6 — Live $300+ (первая статистика)

```
□ Включён режим FIXED_RISK, сайзинг работает, частичные закрытия доступны
□ ≥ 100 сделок
□ Expectancy в R положительна и в пределах доверительного интервала бэктеста
□ Максимальная просадка ≤ 1.5× ожидаемой
□ Метрики исполнения не хуже гейта 5 на 20%
```

### Правило масштабирования (формулируется ДО live и не пересматривается в момент просадки)

```
Повышение:
  - ≥ 100 сделок на текущем уровне, И
  - expectancy в R положительна и в пределах ДИ бэктеста, И
  - максимальная просадка не превысила 1.5× ожидаемой
  → капитал ×1.5 (или риск ×1.5, но не более 0.3%)

Снижение:
  - просадка достигла 60% от p95 Монте-Карло → риск ÷2
  - просадка достигла p95 Монте-Карло → STOP, полный разбор

Остановка проекта:
  - за 6 месяцев live: t-stat < 0 при N ≥ 300 сделок
  → стратегия признана неработающей, капитал выводится
```

> Это правило записывается **до** запуска и не пересматривается в момент просадки. Всё, что решается в момент боли, решается плохо.

## 17.9 Что НЕ является критерием приёмки

- Красивая кривая эквити на in-sample.
- Высокий winrate.
- Большой Profit Factor на малой выборке.
- «Бот работает уже месяц и не сломался» без статистики исполнения.
- Прибыль за короткий период.
- Мнение о том, что стратегия «логичная и должна работать».
