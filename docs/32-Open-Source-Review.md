# 32. Что взять у открытых роботов, а что — нет

> **Дата:** 20 сентября 2026
> **Разобрано:** Freqtrade (54.6 тыс. ★), Hummingbot (20.1 тыс. ★) — по документации и исходникам, а не по обзорам
> **Взято:** метрики оценки, приёмы визуализации, модель Авельянеды–Стойкова
> **Не взято:** наборы индикаторов и сетки подбора параметров — и это главный вывод

---

## 32.1. Главный вывод, ради которого стоило смотреть

Соблазн при разборе чужого робота — выписать список его индикаторов и
добавить себе. Это ровно тот путь, от которого защищает весь наш контур
валидации.

У Freqtrade есть `hyperopt`: перебор сотен комбинаций параметров с
функцией потерь. У нас PBO **0.50** получился уже на грубой сетке из
двенадцати конфигураций (док 27) — то есть каждая вторая «найденная»
конфигурация была бы артефактом перебора. Расширение сетки ухудшает
результат, а не улучшает: это свойство статистики, а не недоработка
инструмента.

**Поэтому взято то, как чужие роботы ПРОВЕРЯЮТ, а не то, что они
считают.** Способ проверки переносится между стратегиями; список
индикаторов — нет.

## 32.2. Визуализация: что у них есть

### Freqtrade / FreqUI

| Элемент | Что показывает | Взяли? |
|---|---|---|
| Trade view | график с отметками входов и выходов | ✅ график с уровнями — есть, отметки сделок появятся с историей |
| Dashboard | сводка по боту; несколько ботов сразу | частично |
| **Wallet balance over time** | баланс с учётом НЕреализованной прибыли, отдельно от «накопленной прибыли» | ⏳ следующий шаг |
| Plot Configurator | настройка индикаторов на графике из UI | ❌ намеренно: см. 32.1 |
| Светлая / тёмная тема | переключатель на видном месте | ✅ есть |
| Адаптивная вёрстка | заявлена | ✅ есть, четыре точки перелома |

Отдельно стоит отметить их честность в мелочи: на графике баланса
Freqtrade рисует линию «Capture start» — момент, с которого данные
достоверны, — и прямо пишет, что до неё значения восстановлены
приблизительно. Это ровно тот подход, что у нас в доке 23 про три
состояния файла: **потеря точности должна быть измеренной, а не
случайной**.

### Чего у обоих нет, а стоило бы

Ни один из них не показывает **почему робот не торгует прямо сейчас**.
Есть логи, есть состояние, есть графики — но нет цепочки проверок с
объяснением, на какой именно решение остановилось. Наш «Путь к сделке»
в этом смысле идёт дальше, и это не случайность: вопрос «почему ничего
не происходит» задаётся чаще любого другого.

## 32.3. Метрики: полный список Freqtrade и что из него взято

Freqtrade печатает по итогам бэктеста около сорока величин. Набор
складывался годами разбора чужих провалов, и в нём мало лишнего.

**Уже было у нас:** число сделок, средняя, t-статистика, доля успеха,
profit factor, максимальная просадка, серия убытков, Sharpe, а сверх
их набора — WFA, CPCV, PBO, Монте-Карло и Deflated Sharpe, которых
у Freqtrade нет вовсе.

**Добавлено** (`src/cashmash/validation/metrics.py`, 16 тестов):

| Метрика | Зачем именно она |
|---|---|
| **Рынок за период** | сравнение с «ничего не делать». Стратегия с +3 % там, где инструмент дал +12 %, проиграла бездействию. Без этой строки любая доходность выглядит достижением — и это самая частая форма самообмана |
| **Sortino** | Sharpe делит на полный разброс и потому наказывает за движение В НАШУ пользу. Для стратегии с редкими крупными выигрышами это меняет вывод на противоположный — закреплено тестом, где Sharpe и Sortino дают разный ответ |
| **Calmar** | доходность к максимальной просадке: сколько придётся пережить ради этой доходности |
| **SQN** (Ван Тарп) | численно та же t-статистика, но со шкалой, к которой привыкли: < 1.6 непригодно, > 2.5 хорошо |
| **Доля времени под водой** | просадка говорит «насколько глубоко», эта величина — «как долго». Второе чаще решает, выдержит ли человек |
| **Длина худшего провала** | то же, но в числе сделок |
| **Матожидание в единицах риска** | сколько получаем на единицу среднего убытка. Отрицательное означает, что стратегия не работает, каким бы ни был winrate |
| **Длительность прибыльных против убыточных** | если убыточные держатся дольше — стратегия «надеется». Это видно числом, а не ощущением |

**Не взято:** CAGR и годовые величины считаются только при явно
переданной частоте сделок. Красивое годовое число, посчитанное по
выдуманному масштабу, хуже прочерка.

## 32.4. Математика: Авельянеда–Стойков

Hummingbot реализует каноническую модель оптимального маркет-мейкинга
(Avellaneda & Stoikov, 2008). Формулы приведены по **исходнику**
`avellaneda_market_making.pyx`, а не по пересказу:

```
резервная цена      r = s − q · γ · σ · T_frac
оптимальный спред   δ = γ · σ · T_frac + (2/γ) · ln(1 + γ/κ)

бид = r − δ/2        аск = r + δ/2
```

| Величина | Смысл |
|---|---|
| `s` | середина рынка |
| `q` | запас относительно целевого, в долях — не в штуках. Иначе размер счёта менял бы резервную цену |
| `γ` | неприятие риска; здесь — доля волатильности, вычитаемая из середины |
| `σ` | волатильность в АБСОЛЮТНЫХ ценах |
| `κ` | ликвидность стакана из подгонки интенсивности `λ(δ) = α·e^(−κδ)` |
| `T_frac` | доля оставшегося времени; для бесконечного горизонта равна 1 |

Смысл модели в одной фразе: **резервная цена смещается против
накопленного запаса**. Набрали длинную позицию — котировки съезжают
вниз, чтобы охотнее продавать и неохотнее покупать. Спред расширяется
с волатильностью и сужается с ликвидностью.

### Честная оговорка из их же исходника

В комментариях Hummingbot прямо написано, что в статье есть ошибки
размерностей: у них в формуле стоит σ (стандартное отклонение), а не
σ² как в оригинале, потому что иначе величина, вычитаемая из цены,
имеет размерность «цена в квадрате». Для бесконечного горизонта авторы
статьи получают выражение, в котором волатильность сокращается
полностью, и Hummingbot заменяет его на конечно-горизонтное с
фиксированным `T_frac = 1`. Это стоит знать всякому, кто будет сверять
реализацию со статьёй.

### Решает ли это НАШУ задачу — нет

Ответ важен, и он отрицательный. Авельянеда–Стойков оптимизирует
**где котировать** при заданном запасе и риске. Он не меняет комиссию.

Док 31 измерил: лучший инструмент из 775 даёт +2.38 bps за круг против
**4.0 bps комиссии мейкера**. Модель может улучшить неблагоприятный
отбор и управление запасом — то есть часть от +2.38, — но комиссия
остаётся снаружи её математики. Разрыв в 1.7 раза она не закрывает.

**Где она понадобится.** Если комиссия когда-нибудь опустится до
уровня окупаемости (VIP 5, док 31), встанет вопрос «как котировать» —
и вот тогда Авельянеда–Стойков будет правильным ответом, а не
самодельная эвристика. Формулы записаны здесь именно поэтому.

## 32.5. Что взято в работу прямо сейчас

| Из чего | Что сделано |
|---|---|
| набор метрик Freqtrade | `validation/metrics.py` + `tests/test_metrics.py` (16 тестов) |
| сравнение с бездействием | поле `benchmark` / `excess` |
| светлая и тёмная тема, адаптивность | четыре точки перелома по читаемости, а не по устройствам |
| честная отметка достоверности данных | уже было (док 23), подтверждено как верный подход |
| Авельянеда–Стойков | формулы записаны и проверены по исходнику; реализация отложена до изменения условий по комиссии |

## 32.6. Что взято НЕ будет

| Что | Почему |
|---|---|
| наборы индикаторов из чужих стратегий | PBO 0.50 уже на 12 конфигурациях (док 27). Каждый добавленный кандидат ухудшает достоверность результата |
| `hyperopt` и подбор параметров перебором | то же самое, в наиболее опасной форме: инструмент сделан, чтобы перебирать много |
| Plot Configurator (индикаторы на графике из UI) | приглашает подбирать глазами — способ поиска закономерностей, у которого нет защиты от переобучения вовсе |
| торговля по новостям как сигнал | отдельно разобрано: новость может только остановить вход (`ops/news_watch.py`) |
