# 🧰 09 · Надёжность и состояние

> Бот работает 8 760 часов в год на машине, которая перезагрузится без спроса, на канале, который оборвётся, у биржи, которая уйдёт на техработы. Проектировать надо не счастливый путь, а восстановление. В крипте это острее, чем на форексе: рынок 24/7, и выходных, в которые можно чинить, не существует.

## 9.1 Три категории состояния

| Категория | Примеры | Источник истины | Хранение |
|-----------|---------|----------------|----------|
| **Авторитетное** | позиция, её размер, стоп, ордера, баланс, история исполнений | **Биржа** | не хранится, запрашивается |
| **Восстановимое** | R позиции, MFE/MAE, стадия сопровождения, время входа | выводится из истории исполнений и цен | SQLite |
| **Накопительное** | дневной baseline equity, счётчик сделок, серия убытков, пик эквити | только локально | **SQLite, транзакционно** |

**Правило 1:** при конфликте локального состояния и биржи прав — биржа.
**Правило 2:** если накопительное состояние утрачено и не восстановимо — старт в `MANAGE_ONLY` с требованием подтверждения оператора. Не «начинаем сутки заново»: это снимает дневной лимит, то есть отключает защиту ровно тогда, когда что-то уже пошло не так.

## 9.2 Почему SQLite, а не набор файлов

Запись «ордер отправлен» и «ордер подтверждён» должны быть согласованы даже при падении процесса между ними. Транзакция даёт это из коробки; два CSV — нет.

```sql
-- эскиз схемы
CREATE TABLE decisions (ts_ms INTEGER, symbol TEXT, side TEXT,
    score REAL, veto TEXT, snapshot_json TEXT, reason TEXT);
CREATE TABLE orders (order_link_id TEXT PRIMARY KEY, ts_send_ms INTEGER,
    status TEXT, order_id TEXT, side TEXT, qty TEXT, price TEXT,
    ret_code INTEGER, ts_reply_ms INTEGER);
CREATE TABLE fills (exec_id TEXT PRIMARY KEY, order_link_id TEXT,
    ts_ms INTEGER, qty TEXT, price TEXT, fee TEXT, is_maker INTEGER);
CREATE TABLE positions (pos_id TEXT PRIMARY KEY, opened_ms INTEGER,
    side TEXT, qty TEXT, entry TEXT, sl TEXT, tp TEXT, r_usdt TEXT,
    stage TEXT, mfe_bps REAL, mae_bps REAL, closed_ms INTEGER);
CREATE TABLE daily (date_utc TEXT PRIMARY KEY, equity_baseline TEXT,
    trades INTEGER, consec_losses INTEGER, equity_peak TEXT);
```

Режим `WAL`, `synchronous = FULL` на торговых таблицах. Потеря последней записи при крахе допустима — она восстановится реконсиляцией; **несогласованное** состояние недопустимо.

Все денежные величины хранятся как `TEXT` и читаются в `Decimal`. `REAL` в SQLite — это float со всеми его проблемами.

## 9.3 Реконсиляция при старте

Выполняется **до** разрешения торговли:

```
1. Проверить связь и авторизацию. Нет — ждать до ReconnectTimeoutSec,
   затем выйти с ненулевым кодом (systemd перезапустит),
   а не стартовать молча в неизвестном состоянии.

2. Синхронизировать часы: GET /v5/market/time → offset.
   |offset| > 2000 мс → PAUSED + алерт.

3. Загрузить спецификации инструмента, сверить с конфигом.
   Расхождение minNotional / qtyStep / tickSize → PAUSED + алерт:
   биржа поменяла правила, пересчитать риск вручную.

4. Собрать состояние биржи: позиции, активные ордера, баланс,
   последние 50 исполнений.

5. Для найденной позиции:
     - восстановить entry, qty, сторону из данных биржи;
     - стоп отсутствует → ВЫСТАВИТЬ НЕМЕДЛЕННО;
     - R восстановить из локального журнала; нет записи —
       из истории исполнений; нет и там — оценить как k×ATR,
       пометить degraded = true и ограничить сопровождение
       (только стоп и тайм-стоп, без трейлинга);
     - определить стадию по текущему уровню стопа.

6. Найти «подвисшие» orderLinkId в журнале со статусом PENDING:
   для каждого — запрос к бирже; исполнен → дописать в журнал;
   не найден → пометить отменённым.

7. Загрузить накопительное состояние по ключу текущей даты UTC.
   Нет записи и сейчас не начало суток → MANAGE_ONLY + алерт.

8. Сверить: число позиций локально == на бирже.
   Расхождение → MANAGE_ONLY + алерт. Не «догадываемся».

9. Только теперь mode = LIVE
```

Повторная реконсиляция — раз в 60 с (лёгкая: позиции и баланс) и всегда после реконнекта WS.

## 9.4 Внутренний watchdog

| Проверка | Период | Порог | Реакция |
|----------|--------|-------|---------|
| Возраст последнего публичного сообщения WS | 1 с | > 5 с | WARN; > 30 с → `MANAGE_ONLY` |
| Возраст приватного WS | 1 с | > 30 с | `MANAGE_ONLY`, сверка REST |
| Последовательность стакана | на каждое обновление | разрыв | пересинхронизация снапшотом, вето на торговлю до восстановления |
| Расхождение часов | 5 мин | > 500 мс | WARN; > 2000 мс → `PAUSED` |
| Позиция без стопа | 1 с | любая | немедленный фикс |
| Использование лимита запросов | постоянно | > 80% | снижение приоритетов |
| Свободное место на диске | 5 мин | < 1 ГБ | остановить запись логов, алерт |
| Память процесса | 5 мин | рост без плато | алерт (утечка) |
| Heartbeat-файл | 10 с | — | запись для внешнего сторожа |

## 9.5 Внешний watchdog (уровень ОС)

Процесс не может перезапустить сам себя, если завис. Двухуровневая схема:

```ini
# ops/cashmash.service
[Service]
ExecStart=/usr/bin/docker run --rm --name cashmash ...
Restart=always
RestartSec=10
StartLimitBurst=5
StartLimitIntervalSec=600     # 5 перезапусков за 10 мин → стоп + алерт
WatchdogSec=60                 # процесс обязан подавать признаки жизни
```

Плюс независимый скрипт `ops/watchdog.py` (systemd timer, раз в 60 с):

```
1. heartbeat.json свежее 120 с?        нет → перезапуск сервиса
2. В heartbeat режим не PAUSED?        PAUSED → алерт, не перезапускать
3. Контейнер жив и отвечает?           нет → перезапуск
4. 3 перезапуска за час?               → НЕ перезапускать, алерт человеку
5. Есть ли открытая позиция при
   мёртвом процессе?                   → алерт наивысшего приоритета
```

Пункт 4 обязателен: бесконечный цикл перезапуска хуже остановки. Бот, который стартует и падает 200 раз за час, каждый раз делая реконсиляцию, — это способ получить HTTP 403 по лимитам.

## 9.6 Обрыв связи: что происходит с позицией

Принять как данность: **при обрыве связи вы не управляете позицией.** Отсюда два следствия:

1. **Биржевой стоп обязателен всегда.** Он живёт на стороне Bybit и сработает, даже если ваш сервер выключен.
2. **Размер позиции должен быть таким, чтобы срабатывание стопа при худшем проскальзывании оставалось приемлемым.** В крипте каскадные движения через стоп — обычное дело; в стресс-тесте закладывается проскальзывание на стопе ×3.

Дополнительно: при восстановлении связи **первым делом** идёт полная сверка, и только потом — любые торговые действия. Соблазн «быстро довыставить стоп по памяти» приводит к действиям на устаревшем состоянии.

## 9.7 Изменения на стороне биржи

| Событие | Как ловим | Реакция |
|---------|----------|---------|
| Изменение `minNotionalValue`, `qtyStep`, `tickSize` | перечитывать спецификации раз в сутки и при старте | расхождение с конфигом → `PAUSED` + алерт |
| Статус инструмента ≠ `Trading` | в спецификациях и в WS | пауза, закрытие позиции если `Delivering`/`Closed` |
| Техработы биржи | ошибки класса MAINT, объявления | пауза до восстановления, без спама ретраями |
| Изменение комиссионного уровня (VIP) | `GET /v5/account/fee-rate` раз в сутки | обновить модель издержек в CostGate |
| Смена режима позиции / плеча извне | сверка при старте и раз в час | несоответствие → `PAUSED` |

Пункт про комиссии не формальность: если уровень комиссии изменился, а `CostGate` считает по старому, робот начнёт брать сделки, которые больше не окупаются.

## 9.8 Детерминизм и воспроизводимость

- Каждое решение пишется в `decisions` **с полным снимком входов** — состояние рынка, голоса детекторов, значения лимитов. Решение должно воспроизводиться из журнала без запуска отладчика.
- В логах и локальное, и биржевое время (по offset).
- Никаких недетерминированных источников в торговом пути: `random` запрещён (джиттер backoff — единственное исключение, и он логируется).
- Порядок обхода коллекций детерминирован.

## 9.9 Тесты надёжности (обязательные)

1. `kill -9` процесса при открытой позиции → после старта позиция под управлением, R корректен, дневной baseline сохранён.
2. Отключение сети на 3 минуты → `MANAGE_ONLY`, после восстановления сверка и возврат в `LIVE`.
3. Удаление `state.db` при живой позиции на бирже → старт в `MANAGE_ONLY`, позиция обнаружена, стоп проверен, R помечен `degraded`.
4. Разрыв WS в момент отправки ордера → идемпотентность отрабатывает, дубля нет.
5. Ручное закрытие позиции через интерфейс биржи → локальное состояние синхронизируется за 60 с без ошибок.
6. Биржа отдаёт 403 → все исходящие остановлены, алерт, позиция под защитой биржевого стопа.
7. Часы переведены на 5 с вперёд → отказ от торговли, ресинхронизация, восстановление.
8. Диск заполнен → логи остановлены, торговля продолжается, алерт отправлен.
9. Инструмент переведён в `Closed` → позиция закрыта, бот в `PAUSED`.
10. 5 перезапусков за 10 минут → systemd останавливает, алерт человеку.
