# 🛡 06 · Риск-менеджмент

> Единственная подсистема с правом вето над всеми остальными. Ошибка сигнального слоя стоит денег линейно. Ошибка риск-слоя стоит депозита целиком — а на перпетуалах ещё и быстрее, чем вы успеете открыть ноутбук.

## 6.1 Два режима сайзинга

Крипта с малым капиталом даёт ситуацию, которой не бывает на форексе: **размер позиции может быть не выбором, а константой**.

### Режим A: фиксированный размер (депозит < ~$100)

Позиция всегда минимальная — `minNotionalValue`, на Bybit это 5 USDT. Риск задаётся **не объёмом, а расстоянием до стопа**:

```
risk_usdt = sl_bps / 10_000 × notional
риск в % от депозита = risk_usdt / equity
```

Пример: депозит $5, позиция $5, стоп 30 bps → риск = $0.015 = **0.3% от депозита**.

Арифметика сходится, но управляющий рычаг инвертирован: вместо «задали риск → получили объём» здесь «задали стоп → получили риск». Следствие: **ширина стопа становится главным параметром риска**, и её нельзя выбирать из соображений «где технически удобный уровень».

Ограничение сверху: `sl_bps ≤ MaxRiskPct × 10_000 × equity / notional`. При депозите $5, позиции $5 и потолке риска 1% это `sl_bps ≤ 100`, то есть стоп не шире 1%.

### Режим B: сайзинг от риска (депозит ≥ ~$300)

Классический и правильный:

```python
risk_usdt  = equity * risk_pct / 100
notional   = risk_usdt / (sl_bps / 10_000)
qty_raw    = notional / price
qty        = floor_to_step(qty_raw, qty_step)

if qty < min_order_qty:              return None   # НЕ торгуем
if qty * price < min_notional_value: return None   # НЕ торгуем
if qty * price / equity > max_leverage_real: clamp or reject
```

**Обязательные проверки:**

| Проверка | Действие при провале |
|----------|---------------------|
| `qty` ниже минимума биржи | **Не торговать.** Не «округлить вверх» — это молча превысит риск |
| Номинал ниже `minNotionalValue` | Не торговать, вето `MIN_NOTIONAL` |
| Реальное плечо `notional/equity` > потолка | Обрезать до потолка; если после обрезки ниже минимума — не торговать |
| Требуемая маржа > свободной × `MarginUsageMax` | Вето `MARGIN` |
| Фактический риск после округления > заданного × 1.05 | Вето |
| Дистанция до цены ликвидации < 3 × ширина стопа | **Вето.** Стоп должен срабатывать сильно раньше ликвидации |

> Считать от **equity**, а не от баланса кошелька. Equity включает нереализованный PnL; сайзинг от баланса при открытой убыточной позиции завышает риск ровно тогда, когда его надо снижать.

## 6.2 Ликвидация — риск, которого нет на споте

На перпетуалах позиция принудительно закрывается биржей, когда маржи не хватает. Ключевые факты:

- ликвидация происходит **по цене банкротства, а не по вашей** — реальный убыток больше расчётного;
- взимается **ликвидационная комиссия**, обычно кратно выше обычной;
- при каскадных движениях исполнение происходит по сильно худшей цене;
- при изолированной марже теряется маржа позиции, при кросс-марже — **весь счёт**.

**Правила проекта:**

```
□ Маржа ИЗОЛИРОВАННАЯ, не кросс.
  Кросс-маржа превращает одну ошибку в потерю всего счёта.
□ Реальное плечо (notional / equity) ≤ 3x, целевое 1x.
□ Дистанция до ликвидации ≥ 3 × ширина стопа. Проверяется ДО отправки.
□ Стоп-лосс на бирже обязателен всегда. Ликвидация не должна быть
  механизмом выхода ни при каких обстоятельствах.
□ Мониторинг: расстояние до ликвидации в bps — метрика на панели,
  алерт при сокращении ниже 5 × стопа.
```

Настройка плеча на бирже влияет только на размер блокируемой маржи и на цену ликвидации. Выставить 3x и открывать позиции размером в 1x эквити — корректная практика: запас маржи есть, реальное плечо единичное.

## 6.3 Иерархия лимитов

```
┌──────────────────────────────────────────────────────────┐
│ УРОВЕНЬ 4 — СЧЁТ                                         │
│  MaxTotalDrawdownPct     20%  → PAUSED, ручной разбор    │
├──────────────────────────────────────────────────────────┤
│ УРОВЕНЬ 3 — НЕДЕЛЯ                                       │
│  MaxWeeklyLossPct         5%  → MANAGE_ONLY до понед.    │
├──────────────────────────────────────────────────────────┤
│ УРОВЕНЬ 2 — СУТКИ (UTC)                                  │
│  MaxDailyLossPct          2%  → MANAGE_ONLY до 00:00 UTC │
│  MaxDailyTrades          30   → MANAGE_ONLY              │
│  MaxConsecutiveLosses     5   → cooldown 60 мин          │
├──────────────────────────────────────────────────────────┤
│ УРОВЕНЬ 1 — СДЕЛКА                                       │
│  RiskPerTradePct       0.3%  (режим B)                   │
│  MaxStopWidthBps        100  (режим A)                   │
│  MaxOpenPositions         1                              │
│  MaxRealLeverage         3x                              │
└──────────────────────────────────────────────────────────┘
```

**Торговые сутки = UTC.** Крипта работает 24/7, естественной границы дня нет; UTC — конвенция биржи и всех данных. Никаких локальных полуночей.

### Как не сломать дневной лимит

Три ошибки, встречающиеся почти в каждом самописном боте:

| Ошибка | Последствие | Правильно |
|--------|------------|----------|
| PnL считается по закрытым сделкам | Плавающий убыток −5% не останавливает торговлю | Считать по **equity**: `daily_pnl = equity_now − equity_baseline_utc` |
| Baseline берётся при старте процесса | Перезапуск в середине суток обнуляет лимит → торговля продолжается после исчерпания | Baseline пишется в SQLite с ключом даты UTC и **переживает перезапуск** |
| Не учитывается уплаченный фандинг и комиссии | Реальная просадка больше расчётной | Equity уже включает всё — ещё одна причина считать по ней |

## 6.4 Динамическое снижение риска по просадке

```
dd = 1 − equity / equity_peak

risk_factor = 1.0                      при dd < 5%
            = 1 − (dd − 0.05) / 0.15   при 5% ≤ dd < 20%
            = 0  → PAUSED              при dd ≥ 20%
```

В режиме A (фиксированный размер) уменьшать объём нельзя — он уже минимальный. Поэтому `risk_factor` там управляет **частотой**: порог входа `EntryThreshold` повышается пропорционально, и робот становится разборчивее вместо того, чтобы торговать меньшим объёмом. Механизм другой, смысл тот же: ошибаешься — снижай ставку.

## 6.5 Kelly как верхняя граница, а не как формула

```
f* = p − (1 − p)/b,    b = avg_win / avg_loss
```

При `p = 0.55`, `b = 1.5`: `f* = 0.55 − 0.45/1.5 = 0.25` — 25% капитала на сделку. Это правильный ответ на неправильный вопрос: `p` оценена по выборке, её ошибка в 3 п.п. меняет `f*` вдвое, а сам критерий допускает просадки за 50%.

**Практика:** `RiskPerTrade ≤ min(0.3%, f*/8)`. Если расчётный `f*` отрицателен — эджа нет, торговать нельзя вообще. Kelly используется как индикатор здоровья стратегии, а не как сайзер.

## 6.6 Money-management режимы

```
FIXED_NOTIONAL     (режим A) минимальный размер, риск через стоп
FIXED_RISK         (режим B) риск % от equity — основной при депозите ≥ $300
ANTI_MARTINGALE    рост размера после серии прибылей, ×1.25, потолок ×2
EXPERIMENTAL       множитель после убытка — ВЫКЛЮЧЕН
```

`EXPERIMENTAL` существует только для честного сравнения на одной серии сделок в Монте-Карло. Включение требует одновременно: явного флага `i_understand_martingale_risk: true`, потолка в 3 шага, и запрета на реальном счёте (проверка `testnet == true`), снимаемого только правкой кода.

Причина обвязки: мартингейл не увеличивает матожидание, он перераспределяет его во времени — превращает распределение в «много мелких плюсов и один терминальный минус». На бэктесте это выглядит идеальной прямой ровно до момента, когда её нет. На перпетуалах с плечом финал наступает быстрее: не «margin call через год», а ликвидация за час.

## 6.7 Фандинг как статья риска

Позиция, открытая в момент расчёта фандинга, платит полную ставку независимо от времени удержания. При ставке 3 bps и позиции $5 это $0.0015 — копейки, но в процентах от ожидаемого эджа (25 bps) это **12%**.

```
□ Вето на вход за 120 с до расчёта
□ Принудительный выход за 30 с до расчёта,
  если только фандинг не в нашу пользу и не превышает стоимость выхода
□ Уплаченный фандинг — отдельная строка в статистике сделки
□ Экстремальная ставка (> 10 bps) → вето на вход в эту сторону:
  это индикатор перекоса позиционирования и повышенного риска сквиза
```

## 6.8 Тесты риск-слоя (обязательные)

1. Сайзинг в режиме B на 5 инструментах с разными `qtyStep` и `minNotional` — фактический риск в пределах ±5% от заданного.
2. Расчётный объём ниже минимума → отказ от сделки, **не** округление вверх.
3. Номинал ниже `minNotionalValue` → вето `MIN_NOTIONAL`.
4. Дневной лимит: симуляция перезапуска процесса в середине суток — baseline сохранён.
5. Граница суток UTC — новый baseline, счётчики сброшены.
6. Просадка 12% → `risk_factor ≈ 0.53`, в режиме A повышен порог входа.
7. Дистанция до ликвидации меньше 3× стопа → вето, а не уменьшение позиции.
8. Расчёт с `float` вместо `Decimal` → тест обязан падать (защита от регрессии).
9. Окно фандинга → вход отклонён, открытая позиция закрыта заранее.
10. Реальное плечо выше потолка → обрезка или отказ, никогда не «ну ладно».
