# 33. Телефоны: что работает на Android, а что на iOS

> **Дата:** 20 сентября 2026
> **Android:** робот работает целиком, и с 20 сентября — **отдельным приложением** (`android/`), без Termux
> **iOS:** панель как приложение на домашнем экране; робот — нет, и это ограничение системы

---

## 33.1. Почему ответ для двух систем разный

Робот — это долгоживущий процесс: он держит открытым WebSocket к бирже,
строит бары и не может «просыпаться по запросу». Разница между
платформами ровно в том, разрешает ли система такой процесс.

| | Android | iOS |
|---|---|---|
| Python внутри приложения | **да**, Chaquopy встраивает CPython в APK | нет: iOS запрещает исполнение загруженного кода |
| Среда с Python | **Termux** — полноценный Linux | нет; a-Shell не держит фон |
| Долгоживущий процесс | **да**, с `termux-wake-lock` | нет: система выгружает фоновые задачи |
| Автозапуск при перезагрузке | **да**, Termux:Boot | нет |
| Панель как приложение | да | **да** |

Поэтому на Android робот живёт целиком, а на iOS телефон — это экран
к роботу, который работает на компьютере или сервере. Обещать «робот на
айфоне» было бы неправдой: ограничение не в нашем коде.

## 33.2. Панель как приложение — обе системы

Панель сделана устанавливаемой (PWA): манифест, иконки, полноэкранный
режим, учёт выреза экрана.

**Android (Chrome):** открыть панель → меню → «Установить приложение».
Появится иконка, приложение откроется без адресной строки.

**iOS (Safari):** открыть панель → «Поделиться» → «На экран Домой».
Safari не читает манифест, поэтому режим и иконка заданы отдельными
тегами `apple-mobile-web-app-*` — без них открылась бы обычная вкладка.

Что сделано для экрана телефона:

* `viewport-fit=cover` плюс `env(safe-area-inset-*)` — иначе шапка
  уезжает под вырез, а подвал под полосу жеста;
* `overscroll-behavior-y: none` — панель обновляется сама, и жест
  «потянуть для обновления» только мешает;
* выделение текста при долгом нажатии отключено на сенсорных
  устройствах: цифры отсюда не копируют, а прокрутке оно мешает;
* иконки нарисованы своим кодировщиком PNG (`ops/make_icons.py`) —
  ради четырёх файлов по килобайту тянуть Pillow на телефон незачем;
* вариант `maskable` с полями 20 %: Android обрезает иконку под форму
  темы, и без полей рисунок срезается.

### Честная оговорка про офлайн

Сервис-воркер (`ops/sw.js`) кэширует оболочку, но **никогда не кэширует
`/api/state`**: устаревшее состояние счёта хуже отсутствующего — цена
двухминутной давности выглядит как текущая.

Работает он только в защищённом контексте: `localhost` или HTTPS.
Панель, открытая с телефона по локальной сети через обычный HTTP, воркер
не зарегистрирует. Это не ошибка: установка на домашний экран,
полноэкранный режим и иконка обеспечиваются манифестом и тегами, а не
воркером. Регистрация обёрнута проверкой `window.isSecureContext`.

**Проверить регистрацию воркера в этой среде не удалось:** встроенный
браузер блокирует регистрацию любого скрипта, включая заведомо
существующий. Всё остальное — манифест, иконки, теги, вёрстка —
проверено. Воркер проверяйте на настоящем телефоне.

## 33.3. Android: приложение

```
android/          проект приложения
  app/src/main/java/…   оболочка на Kotlin
  app/src/main/python/  стык с роботом
ops/android_run.py      супервизор внутри одного процесса
```

Сборка на машине с Android SDK:

```bash
cd android
./gradlew assembleDebug        # android/app/build/outputs/apk/debug/app-debug.apk
./gradlew installDebug         # сразу на подключённый телефон
```

Перед первой сборкой в `android/local.properties` нужны два пути —
к Android SDK и к Python той же младшей версии, что зашита в
`app/build.gradle.kts` (сейчас 3.13): этим интерпретатором Chaquopy
запускает pip, собирая колёса под Android.

```properties
sdk.dir=C:/Users/имя/AppData/Local/Android/Sdk
chaquopy.buildPython=C:/путь/к/проекту/.venv/Scripts/python.exe
```

### Что именно лежит в APK

Настоящий CPython (Chaquopy), три библиотеки (`websockets`, `requests`,
`PyYAML`) и дерево робота целиком — `src/`, `ops/`, `config/`,
`research/collect_bybit.py`. Логика на телефоне та же, что на
компьютере, файл в файл; отдельной «мобильной версии робота» нет и
заводить её нельзя — разошлись бы поведением.

`ops/.env` в APK **не попадает никогда**: APK копируют, пересылают и
забывают в загрузках, а там токен Telegram и, возможно, ключи биржи.
На телефоне файл создаётся заново, из настроек приложения, и лежит во
внутренней памяти.

### Три решения, которые определили устройство приложения

**Службы стали потоками одного процесса.** `ops/run.py` запускает
каждую службу отдельным процессом — на телефоне запускать нечего:
Chaquopy даёт интерпретатор библиотекой, исполняемого файла `python`
не существует. Поэтому `ops/android_run.py` поднимает те же службы
потоками. Цена — потеря изоляции: падение одной может задеть общий
процесс. Что это потребовало починить, описано ниже.

**Робот живёт в отдельном процессе приложения** (`:bot`). Экран и
робот разделены: остановка робота не закрывает приложение, а падение
панели не уносит сбор. Разговаривают они через ту же локальную
панель, что и на компьютере, — отдельного протокола не понадобилось.

**Тип службы — `specialUse`, а не `dataSync`.** С Android 15 службы
типа `dataSync` живут не больше 6 часов в сутки: система гасит их
сама. Робот, замолкающий в середине дня и не объясняющий почему, хуже
робота, которого нет. Плата за `specialUse` — приложение нельзя
опубликовать в Google Play без обоснования; для личной сборки это не
мешает.

### Что пришлось починить при переходе к потокам

| Что ломалось | Почему | Решение |
|---|---|---|
| Аргументы служб | `sys.argv` один на процесс — вторая служба затирала первую | `parse_args` берёт argv из переменной, локальной для потока; общий `sys.argv` не трогается |
| Обработчики сигналов | `add_signal_handler` работает только в главном потоке | исключение перехвачено; остановка приходит завершением процесса |
| Журналы | `print` из всех потоков шёл в один поток | `sys.stdout` — маршрутизатор: служба → свой файл в `data/logs/`, потолок 2 МБ и одно поколение назад |
| `pydantic` | ядро на Rust, колеса под Android не существует | `src/cashmash/core/_minimodel.py` — замена на том подмножестве, что использует конфиг; сверяется с оригиналом в `tests/test_minimodel.py` |

Замена pydantic — единственное место, где телефон и компьютер
исполняют разный код. Поэтому тест сверяет не «работает ли замена», а
совпадают ли два разбора одного конфига, включая отпечаток
риск-профиля: конфиг, отвергнутый на компьютере, не должен
запускаться на телефоне.

### Четыре вкладки

Сначала приложение было одним экраном: панель робота во всю высоту и
строка состояния над ней. Панель отвечает на вопрос «что робот видит и
решает» — и отвечает хорошо. Но три других вопроса ей не задать: жив ли
процесс и что ему мешает, что он писал в журнал, как он настроен. Они
ютились по углам — состояние в одной обрезанной строке, журнал и
настройки за отдельными экранами, куда вела единственная шестерёнка.

Разделение идёт по **роду содержимого**, а не по темам: это разные
вопросы, задаются они в разное время, и на одном экране мешают друг
другу.

| Вкладка | Отвечает на вопрос |
|---|---|
| **Робот** | жив ли процесс, какая служба отказала и почему, что с сетью и местом |
| **Панель** | что робот видит и решает прямо сейчас |
| **Журнал** | что он писал, когда никто не смотрел |
| **Настройки** | как он настроен |

Полоса управления — состояние и кнопка пуска — не принадлежит ни одной
вкладке и висит сверху всегда. Остановить робота человек захочет с
любого экрана, а узнать, жив ли он, — тем более; прятать это в одну из
вкладок значило бы заставлять туда возвращаться.

Навигация внизу, а не вверху: телефон держат одной рукой, и большой
палец достаёт до низа экрана.

**Вкладки живут одновременно, а не пересоздаются.** Панель внутри
`WebView` иначе перезагружалась бы при каждом возвращении — полсекунды
на разбор страницы и потерянная прокрутка. Но спрятанная вкладка обязана
замолчать, поэтому ей принудительно опускается жизненный цикл до
`STARTED`: она получает `onPause` и останавливает свой опрос. Измерено:
процессорное время процесса панели за 12 секунд — **30 тиков на
открытой вкладке и 0 на скрытой**. Проверено и обратное: экран после
ухода на другую вкладку и возврата совпадает попиксельно, то есть
страница не перезагружалась.

**Без смахивания, намеренно.** Нижняя навигация и смахивание между
экранами не сочетаются: под пальцем оказывается то горизонтальная
прокрутка журнала, то содержимое панели, и жест угадывается неверно.
Переход делается нажатием и анимируется по направлению — влево или
вправо, смотря куда идёт человек: направление говорит, куда ты пошёл, и
возврат ощущается возвратом.

#### Что вкладка «Робот» показывает сверх прежнего

Состояние каждой службы отдельной строкой: точка цвета, название,
зачем она нужна и что с ней сейчас. Причина отказа стоит в той же
строке — «alerts не поднялся» без продолжения это загадка, а «не задан
токен Telegram» это инструкция. Плюс время работы, состояние сети,
занятое данными место и адрес панели.

Внутренние пути из причин убираются при показе: служба честно пишет
«ожидался в /data/user/0/…/ops/.env», но на телефоне туда без root не
попасть, а токен вписывается в настройках. Полный текст, вместе с
путём, остаётся в журнале.

#### Ошибка, которую поймала эта переделка

Свежесть снимка учитывалась только в одном месте — для панели. Список
служб её не проверял, и при устаревшем файле экран начинал спорить сам
с собой: заголовок «Остановлен», а точки служб зелёные. Теперь
свежесть применяется один раз, при чтении файла: несвежий снимок не
может объявить живой ни одну службу, и все потребители согласованы по
построению.

### Что приложение делает своими руками

* **Распаковывает дерево робота** из APK в рабочий каталог при первой
  установке и при каждом обновлении. Код заменяется целиком, `data/`,
  `config/` и `ops/.env` не трогаются никогда: первое принадлежит
  сборке, второе — человеку.
* **Держит процесс живым**: служба переднего плана и `PARTIAL_WAKE_LOCK`.
  Уведомление скрыть нельзя — это не украшение, а условие жизни
  процесса.
* **Показывает панель** в `WebView` по адресу 127.0.0.1 — на своей вкладке.
  Второй панели
  средствами Android нет и не будет: две картины одного состояния
  однажды разойдутся.
* **Объясняет, когда панели нет.** Пустой белый экран — худший исход:
  по нему не понять, робот ли стоит, порт ли занят или страница ещё
  грузится.
* **Поднимается после перезагрузки** — только если включено в
  настройках и робот работал до выключения.

### Что включено по умолчанию

| Служба | По умолчанию | Почему |
|---|---|---|
| `dashboard` | включена | то, что видно в приложении |
| `paper` | включена | виртуальная торговля и самопроверка |
| `news` | включена | новости могут только остановить торговлю |
| `alerts` | включена | без токена честно отказывается и не перезапускается |
| `collector` | **выключен** | около 65 МБ в сутки на память телефона |
| `trader` | **выключен** | требует ключей биржи |

Телефон по умолчанию наблюдает: считает решения вхолостую, следит за
новостями и шлёт сообщения. Запись истории и торговля включаются
руками, и цена каждой названа прямо в строке выбора.

Параметры торговли — риск, издержки, геометрия сделки — в настройках
приложения намеренно отсутствуют. Они живут в YAML-конфиге, проверяются
кодом робота и ограничены жёсткими потолками. Ползунок «риск на
сделку», который правится большим пальцем в метро, — ровно тот способ
потерять счёт, от которого проект защищается.

### Размер и подпись

Сборка даёт APK на каждую архитектуру отдельно и один универсальный:

| Файл | Размер |
|---|---|
| `app-arm64-v8a-debug.apk` | 28.9 МБ ← для телефона |
| `app-x86_64-debug.apk` | 28.9 МБ ← для эмулятора |
| `app-universal-debug.apk` | 39.3 МБ |

Разделение снимает треть веса, а не половину: нативных библиотек тут
немного, основную массу составляют сам Python и его стандартная
библиотека, одинаковые для обеих архитектур.

Минификация (R8) намеренно выключена. Chaquopy связывает Python и Java
рефлексией, и убедиться, что сокращение ничего не порвало, можно только
запуском на устройстве; выигрыш в размере при этом дают разделённые
ABI, а не R8, — риск не окупается.

Подпись release-сборки настраивается, но ключ создаёт человек, а не
сборка: пароль не должен попадать в репозиторий.

```bash
keytool -genkeypair -v -keystore cashmash.jks -alias cashmash \
        -keyalg RSA -keysize 4096 -validity 10000
```

Затем в `android/local.properties`:

```properties
release.keystore=C:/путь/к/cashmash.jks
release.storePassword=…
release.keyAlias=cashmash
release.keyPassword=…
```

Ключ нельзя терять: обновление приложения принимается, только если
подписано тем же ключом. Нет этих строк — `assembleRelease` соберёт
неподписанный APK, и это видно сразу, а не после неудачной установки.

### Отпечаток дерева робота

Распаковка сверяется с SHA-256 по содержимому упакованных файлов, а не
с версией приложения. Так было не сразу: сначала отпечаток считался по
`versionCode`, и это давало тихий дефект — правка в Python попадала
в APK, но распаковка её не замечала (версия-то прежняя), приложение
обновлялось, а робот продолжал работать по старому коду. Заметить это
можно было только сравнив файлы вручную.

### Место под записанные данные

Сбор пишет около 65 МБ в сутки и сам ничего не удаляет. На компьютере
это осознанная плата, на телефоне — ловушка: данные лежат во внутренней
памяти приложения, их не видно файловым менеджером и нельзя почистить
выборочно; единственный доступный способ освободить место — стереть
данные приложения, а вместе с ними уйдут `ops/.env` и состояние
виртуальной торговли.

Поэтому в настройках есть потолок (по умолчанию 2 ГБ). Правила
в `ops/housekeeping.py` и закрыты тестами:

* **без явного потолка не удаляется ничего** — ноль означает «не
  трогать», и умолчание для компьютера именно такое;
* **файл под записью неприкосновенен** — самый свежий по каждому
  символу пропускается всегда;
* **удаление не бывает молчаливым** — каждый файл называется в журнале.

### Журналы на экране

Причина отказа службы лежит в `data/logs/`, во внутренней памяти
приложения: на телефоне без root туда не добраться ничем. Подсказка
«смотрите data/logs/dashboard.log» была советом, которому невозможно
последовать. Поэтому в приложении есть экран журналов — выбор файла,
хвост в 200 КБ, кнопка «поделиться» через `FileProvider`. Провайдер
отдаёт наружу только каталог логов: `ops/.env` лежит рядом, но
недоступен.

### Панель в локальной сети

Опция «показывать панель в локальной сети» показывает готовый адрес
с токеном и кнопку «скопировать»; токен хранится между запусками
(иначе сохранённая ссылка ломалась бы при каждом перезапуске) и
меняется по кнопке «сменить токен».

### Сеть, за которую платят

Робот держит открытым поток стакана — это сотни мегабайт в сутки даже
без записи на диск. На домашнем Wi-Fi это ничего не стоит, на сотовой
связи превращается в счёт, который человек увидит через месяц и не
свяжет с приложением. Поэтому по умолчанию включено «работать только в
безлимитной сети».

Проверяется **не** «Wi-Fi ли это». Wi-Fi в поезде и раздача с другого
телефона тарифицируются так же, как сотовая связь, и система сама
помечает такие сети признаком `NET_CAPABILITY_NOT_METERED`. Спросить у
неё честнее, чем угадывать по типу подключения. Отсутствие сети
тарифицируемым не считается: данные всё равно не идут, а службы умеют
переподключаться сами.

Поведение:

| Событие | Что делает приложение |
|---|---|
| Пуск в платной сети | не поднимает Python вообще и пишет причину на экране |
| Сеть стала платной на ходу | останавливает робота так же, как кнопка «Стоп», и ставит признак паузы |
| Приложение открыли в безлимитной сети | поднимает робота сам и сообщает об этом |

Возвращение сделано именно так — по открытию приложения, а не по
появлению Wi-Fi, — потому что Android запрещает фоновым приложениям
поднимать службы переднего плана. Попытка «вернуться самому» упёрлась
бы в этот запрет, причём молча. Цена честная: робот вернётся не в тот
миг, когда появился Wi-Fi, а когда на него посмотрят.

**Признак паузы хранится файлом, а не настройкой.** Это вторая ошибка,
которую поймала проверка на эмуляторе. Робот живёт в отдельном
процессе, а `SharedPreferences` между процессами не синхронизируются:
каждый держит свой снимок в памяти и файл не перечитывает. Флаг,
выставленный роботом, экран просто не видел — сеть была уже
безлимитной, робот стоял, а приложение считало, что останавливать его
было некому. Файл на диске читают оба процесса, и оба видят одно и то
же.

Общее правило, которое из этого следует: в `Prefs` живёт только то, что
**пишет экран**, а робот читает при запуске — он стартует заново и файл
перечитывает. Состояние в обратную сторону идёт файлом.

### Совет на панели зависит от площадки

Панель говорила «запустите `ops\collect.cmd`» — путь Windows на экране
телефона. Теперь площадку сообщает сервер (`CASHMASH_PLATFORM`
выставляется мостом приложения, а панель кладёт его в `/api/state`), и
на телефоне совет другой: «включите collector в настройках приложения».

Именно сервер, а не браузер: панель телефона открывают с компьютера и
наоборот, так что совет должен зависеть от того, ГДЕ работает робот, а
не откуда смотрят. Старые сборки, где ключа ещё нет, попадают в ветку
«компьютер» — то есть ведут себя ровно как раньше.

---

### Расход батареи

Свёрнутое приложение больше не опрашивает робота: `WebView` ставится на
паузу вместе с таймерами JavaScript. Измерено на эмуляторе — процессорное
время процесса панели за 15 секунд: **39 тиков на переднем плане против
4 в фоне**. До этого панель продолжала обновляться раз в секунду
бесконечно, за тем, чего никто не видит.

---

### Что проверено

Собрано и проверено на эмуляторе Pixel 7 Pro (Android 37, x86_64):
распаковка 73 файлов за 83 мс, старт Python 3.13, три службы
(`dashboard`, `paper`, `news`) поднялись, `alerts` отказался из-за
отсутствия токена и не ушёл в цикл перезапуска, панель отрисовалась в
приложении, остановка убила процесс робота и не тронула экран.
Проверены также экран журналов, адрес с токеном для локальной сети,
потолок на объём данных и пауза панели в фоне (39 тиков процессора
против 4 за 15 секунд).

Поведение при смене сети проверено все четыре ветки: запуск в
безлимитной сети, остановка при переходе на платную, отказ запускаться
на платной с причиной на экране и самостоятельный подъём при
возвращении. Тарификация переключалась командой
`adb shell cmd netpolicy set metered-network AndroidWifi true`.

**На настоящем телефоне не проверялось.** Эмулятор не отвечает на два
вопроса: как поведёт себя Doze на реальном устройстве и сколько
продержится батарея. Ожидание — расход заметный: wake-lock не даёт
процессору уснуть, в этом его смысл.

### Расход батареи и памяти

То же, что и через Termux: постоянный WebSocket, процессор не спит.
Телефон на зарядке для многонедельной работы подходит, телефон в
кармане — нет. Сбор данных (`collector`) добавляет около 65 МБ в сутки
на память.

## 33.4. Android без сборки: Termux

Путь для тех, кому не нужен APK: то же самое, но из терминала.

```sh
sh ops/android_termux.sh
```

Скрипт ставит Python и библиотеки, включает `termux-wake-lock`, создаёт
автозапуск и поднимает всё.

**Что нужно заранее:** Termux и Termux:API из **F-Droid** (версия из
Google Play устарела и не обновляется), а для автозапуска — Termux:Boot,
запущенный хотя бы раз: без первого запуска Android не даёт ему
стартовать. Это требование из официального README Termux:Boot, а не
догадка.

**Чего ждать реалистично.** Телефон тянет сбор данных, виртуальную
торговлю и панель. Расход — около 65 МБ в сутки на диск и постоянный
WebSocket. Батарея будет садиться заметно быстрее: wake-lock не даёт
процессору уснуть, в этом его смысл. Для многонедельного сбора телефон
на зарядке подходит, телефон в кармане — нет.

## 33.5. iOS: панель и уведомления

Установка на домашний экран описана выше. Что получится:

* полноэкранная панель со своей иконкой, без адресной строки;
* всё то же содержимое: путь к сделке, детекторы, стакан, лента,
  виртуальная торговля, новости;
* обновление раз в секунду, пока приложение открыто.

Чего **не** получится: работы в фоне и уведомлений о событиях, когда
приложение закрыто. Для этого у проекта уже есть Telegram
(`ops/alert_agent.py`) — он доставляет алерты на любой телефон и не
зависит от того, открыта ли панель. Это и есть правильное разделение:
панель для просмотра, Telegram для оповещения.

Чтобы телефон видел панель, робот запускается с доступом по сети:

```
.venv\Scripts\python.exe start.py --host 0.0.0.0
```

Доступ закрывается токеном — он печатается в ссылке при запуске
(док про панель). В чужой сети надёжнее SSH-туннель: HTTP не шифрован.
