# 🎛 08 · Управление позицией

## 8.1 Жизненный цикл

```
PENDING_ENTRY  (post-only заявка выставлена)
  │
  ├─ [не исполнена, цена ушла] ─▶ CANCELLED → сигнал пропущен
  │
  ▼
OPENED  (стоп на бирже подтверждён)
  │
  ├─ [PnL ≥ +0.8R] ──────────▶ BREAKEVEN_ARMED   SL → entry + издержки
  ├─ [PnL ≥ +1.0R] ──────────▶ PARTIAL_TAKEN     только если размер позволяет
  ├─ [PnL ≥ +1.2R] ──────────▶ TRAILING          SL = extreme − k×ATR
  │
  ├─ [hold > T_soft и PnL < 0.5R] ─▶ TIME_EXIT_SOFT
  ├─ [hold > T_max] ─────────▶ TIME_EXIT_HARD
  ├─ [до фандинга < 30 с] ───▶ FUNDING_EXIT
  ├─ [kill-switch / CHAOS / 403] ─▶ EMERGENCY_EXIT
  │
  ▼
CLOSED → учёт, MFE/MAE, комиссия, фандинг, телеметрия
```

## 8.2 Безубыток: не в ноль

Перевод стопа ровно в цену входа фиксирует убыток размером в круг издержек. Правильный уровень:

```
BE_long  = entry × (1 + (fee_round_bps + 1) / 10_000)
BE_short = entry × (1 − (fee_round_bps + 1) / 10_000)
```

При круге 7.5 bps это entry + 8.5 bps — то есть «безубыток» на XRPUSDT находится примерно в 0.085% от входа, а не в нуле.

**И второе: BE не должен срабатывать рано.** Перевод в BE на +0.3R превращает нормальный шум в серию мелких выходов и убивает правый хвост распределения — тот самый, за счёт которого система зарабатывает. Порог 0.8R — стартовый; в отчёте обязательна метрика «сколько сделок, выбитых по BE, дошли бы до TP».

## 8.3 Трейлинг

| Тип | Формула | Когда |
|-----|---------|-------|
| ATR-трейлинг (по умолчанию) | `SL = max(SL, extreme − k×ATR)` | универсально |
| По структуре | последний свинг ± буфер | трендовые сетапы |
| Временной | `k` уменьшается с ростом времени удержания | скальпинг: чем дольше висим, тем меньше доверия |

Требования:

- **только в сторону прибыли** — проверка, что новый уровень строго лучше;
- **не чаще `TrailMinStepBps`** (по умолчанию 5 bps) — иначе это флуд запросов и расход лимита из [[21-Rate-Limits-and-Bans]];
- каждое изменение стопа — это запрос к бирже приоритета P1; при дефиците бюджета трейлинг **замораживается, а стоп остаётся на месте**, а не снимается;
- изменение стопа идёт через тот же `OrderRouter` с идемпотентностью.

## 8.4 Частичное закрытие — на малом депозите невозможно

```python
qty_close = floor_to_step(qty_total * partial_pct, qty_step)
if qty_close < min_order_qty:                  skip_partial()
if (qty_total - qty_close) < min_order_qty:    close_all()
if (qty_total - qty_close) * price < min_notional: close_all()
```

При позиции минимального размера (5 USDT) **любое частичное закрытие оставляет остаток ниже минимума**, то есть частичные закрытия недоступны. Это не баг конфигурации, а свойство депозита: модуль обязан это понимать и не слать заведомо невалидные запросы.

Функция включается сама, когда депозит вырастает настолько, что позиция становится кратна минимуму хотя бы вдвое.

После частичного закрытия **R не пересчитывается**: пороги трейлинга считаются от исходного риска, иначе логика «поедет» после каждой фиксации.

## 8.5 Тайм-стоп — обязателен

У короткоживущих сетапов сделка, не пошедшая в плюс за первые N секунд, статистически хуже средней. Держать её — платить время и риск за отрицательное матожидание.

```
T_soft = P70(время до +1R у выигрышных сделок из бэктеста)
T_max  = 3 × T_soft
```

Параметр задаётся **перцентилем, а не числом минут**: перцентиль переносится между инструментами и режимами волатильности, число минут — нет.

Выход по тайм-стопу — `Market` + `reduceOnly`, то есть taker. Это 5.5 bps — надо закладывать в модель издержек: сделка, закрытая по времени, стоит дороже, чем закрытая по TP мейкером.

## 8.6 Аварийные сценарии

| Событие | Реакция |
|---------|---------|
| Приватный WS молчит > `WsSilenceSec` (30 с) | Новые входы запрещены; сверка через REST; стоп на бирже продолжает защищать позицию |
| Оба WS мертвы, REST жив | `MANAGE_ONLY`, сверка по таймеру, алерт |
| HTTP 403 (бан) | Полная остановка исходящих. Позицию **не закрываем** — нечем. Защищает биржевой стоп. Алерт с наивысшим приоритетом |
| Спред > `PanicSpreadBps` | Вето на вход. Закрытие **не** форсируем: закрываться в этот момент — платить именно этот спред |
| Позиция обнаружена без стопа | 3 попытки выставить → аварийное закрытие + алерт |
| Позиция, которой нет в локальном учёте | Принять под управление, R восстановить из истории исполнений; не нашли — оценить как `k×ATR` и пометить `degraded` |
| Локальный учёт видит позицию, которой нет на бирже | Синхронизировать по бирже, разобраться по логам, алерт |
| Чужая активность на том же аккаунте (ручные сделки) | Обнаруживается по несоответствию; `MANAGE_ONLY` + алерт. Отдельный субаккаунт под бота снимает проблему |
| Kill-switch | `FLATTEN`: закрыть по рынку с ретраями, затем `PAUSED` |

> Про «не закрываем при потере связи»: это не покорность судьбе, а арифметика. При обрыве вы физически не можете отправить ордер. Единственное, что защищает позицию, — стоп, стоящий **на бирже**. Отсюда требование 7.5: биржевой стоп обязателен всегда, локальный — только как дополнительный, более близкий.

## 8.7 MFE / MAE

Для каждой позиции ведём максимальную благоприятную и максимальную неблагоприятную экскурсию, в bps и в R. Обновляются по обновлению цены, пишутся при закрытии.

Зачем: это единственный способ ответить, не рано ли мы фиксируем и не слишком ли далёк стоп, без гадания. Если медианный MAE выигрышных сделок = 0.3R, стоп в 1R избыточен — его можно ужать и улучшить RR без потери winrate.

## 8.8 One-way mode

Bybit поддерживает one-way и hedge. Проект принудительно использует **one-way** с проверкой при старте:

- одна позиция на символ, направление меняется через закрытие;
- встречный сигнал = закрытие текущей позиции, **не переворот** одним ордером (переворот ломает учёт R и тайм-стопа);
- `reduceOnly` на всех закрывающих ордерах — защита от случайного открытия противоположной позиции при гонке.
